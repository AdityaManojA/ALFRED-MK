## Problems to fix first

1. **API-key fallback raises NameError.** `main.py:398–404` uses `os.environ` but only imports `os as _os`. Missing/unreadable configuration or an absent Gemini key reaches this broken fallback. `core/llm_client.py:70,76,99` also uses `os.environ` without importing `os`; OpenAI-compatible/OpenRouter environment-key fallback fails. Reproduced with mocked empty configuration, without network calls. Fix the imports/alias and test missing files, missing keys, environment-only keys, and invalid JSON.

2. **The main assistant worker bypasses the new crash dialog.** `main.py:88` retains a separate `threading.excepthook`; the assistant runs in a daemon thread at `main.py:3694`. Its exceptions go to `config/crash.log`, whereas `core/crash_handler.py:121` installs only `sys.excepthook`. Route worker failures to a GUI-thread signal or independent reporting process and unify log storage. Native crashes and process termination are also outside Python exception hooks; do not claim universal crash coverage.

3. **Duplicate local-speech method overrides the intended TTS engine.** `main.py:3206` replaces `_speak_local` from line 1672. The effective implementation directly uses Windows SAPI, starts a thread per utterance, and silently swallows exceptions, bypassing `core.tts.get_engine()`. On systems without win32com it silently produces no speech. Consolidate the methods, use one bounded speech worker, preserve selected voice settings, and surface synthesis failures.

4. **Model warm-up never runs.** `main.py:3275` calls `asyncio.to_thread(warmup_model, system_instruction)` without awaiting or scheduling it. This creates a coroutine but does not run the function. Await it or retain a scheduled task with error handling and cancellation. This directly undermines the intended reduction in first-response latency.

5. **Reporting a long crash can freeze the dialog.** `core/crash_handler.py:91–94` repeatedly URL-encodes the whole body and removes one character per iteration. Isolated measurements with a mocked launcher: 5,000 characters = 0.50 s; 10,000 = 1.98 s; 20,000 = 8.48 s. Use a bounded, one-pass encoded-byte budget or binary search. Keep the error and log location even when trimming. This is a defect in the crash feature added immediately before this audit.

6. **GPU capability detection confuses “not inspected” with “no CUDA.”** `core/tts/capability.py:54` returns no CUDA whenever torch has not already been imported. The result is cached for 60 seconds. The cold-process probe confirmed that behavior; it does not prove the machine lacks a GPU. Perform the expensive inspection in a worker, show a checking state, and invalidate capability state after initialization/download/configuration changes.

## Latent defects and performance warnings

- **Local audio coordinator blocks its event loop.** `core/local_pipeline.py:250` performs synchronous `Queue.get(timeout=0.1)` inside an async loop; the empty-queue branch immediately continues without an async yield. A controlled five-iteration probe blocked another task for 504 ms. Streaming LLM iteration and transcription are also synchronous there. The coordinator appears imported but not activated by current main startup, so this is a serious enablement risk rather than demonstrated current UI lag. Use an async queue with thread-safe producer handoff, and move blocking inference to workers.
- **Local pipeline has unfinished functionality.** `core/local_pipeline.py:88` calls undefined `call_llm`; its tool handler returns placeholder results rather than dispatching tools. The VAD compares raw int16-scale RMS against 0.01 at line 267, and its buffer has no duration cap. Complete/test the path before enabling it; normalize samples and bound utterance duration.
- **An unused duplicate popup class crashes on construction.** `ui.py:5258` has unescaped CSS braces in an f-string, producing `NameError: background`. Reproduced with a real offscreen QApplication. The active image action uses the separate class in `actions/show_image_popup.py`, so this is not evidence that the active image action is broken. Remove the duplicate or fix and test it.
- **Long-running sessions can accumulate work and history.** The receive-audio queue (`main.py:3498`), background-job queue (`main.py:896`), and local conversation history (`main.py:3272` onward) are unbounded. This creates potential memory growth and delayed audio under producer/consumer imbalance. Bound queues by a latency/duration budget, define cancellation/overflow behavior, and trim history by tokens. No sustained-session leak was measured.
- **Startup imports are substantial.** A fresh-process `import main` took 2.61 s; `google.genai` accounted for 1.68 s cumulatively. Defer provider-specific imports until that provider is selected, and avoid loading inactive pipelines. This measures imports only, not time to an interactive window or a guaranteed achievable speedup.
- **GC tuning needs measurement.** `main.py:107` raises generation-zero threshold to 70,000 and runs full collection every 45 seconds during silence (`main.py:3004`). Moving collection to a thread does not establish that UI/audio pauses disappear. Measure collection duration, Qt event-loop gaps, and RSS before changing these values further.
- **UI log rendering can be cheaper.** `ui.py:3715` starts a 6 ms typing timer and processes small character chunks. The visible document is capped at 600 blocks, which is good, but pending messages are stored in an unbounded list and removed with `pop(0)`. Use a deque, batch inserts per frame, and skip typing animation when a backlog grows.
- **Cache utility has correctness/performance traps.** `core/cache.py:67` converts primitive values to strings; `build_key('audit', 1)` equals `build_key('audit', '1')`, reproduced. Runtime Redis failures are retried on subsequent operations instead of activating a circuit breaker; eviction scans entries while locked and capacity is entry-count based, not byte based. Fix before broadening use. No active decorator consumers were found in the searched actions/core code, so do not treat this as a proven present bottleneck.
- **Performance probe CPU figures are unreliable.** `tools/profile_alfred_ui.py:55–57` creates a fresh `psutil.Process()` on each sample and immediately calls nonblocking `cpu_percent`. Retain and prime one process object to measure an interval; otherwise first-sample CPU values can misleadingly be zero.
- **Missing Windows package.** `winsdk` is declared but absent. The media suppressor catches this and falls back to pycaw (`core/media/suppress/win.py:34`); native media-session pause behavior is therefore unavailable through that path. `pip check` alone does not detect missing project requirements.

## Test failures and warnings: what they mean

| Failure group | Assessment / next step |
|---|---|
| HUD allocation test | 8,992 positive-delta bytes vs 2,048 allowed in suite; passed in isolation. The measurement includes tick and paint and sums process-wide positive tracemalloc deltas. Isolate allocations and measure retained growth; this is not proof of a production leak. |
| Jarvis capability tests | Cache survives between tests. The mocked “all capabilities available” case passed alone; different test order changed which cases failed. Reset the cache per test or use `use_cache=False` for component tests, with separate cache tests. |
| Sentry menu tests | Expect 2 actions / 5-second routing while current code provides 4 actions / 3 seconds. Confirm intended behavior, then update the appropriate contract. |
| Sentry snapshot test | Constructs `SentrySnapshot` without required timestamp, so it fails before exercising the intended exception boundary. |
| Minimized HUD test | Calls a native QMainWindow method with MagicMock as `self`; fails Qt type checking. Use a real offscreen widget or test extracted logic. |
| Remote overlay flash test | Checks `isVisible()` while its parent is never shown. Show/process events or assert the local hidden state as appropriate. |
| Screen-find integration | Patches pyautogui screenshot, but production capture tries mss first. The test can inspect the real desktop and reach cloud fallback; the slowest call took 18.11 s. Mock the capture seam and provider; keep hardware/network tests separately marked. |
| Deferred annotations | Missing `List`, `QPaintEvent`, `QMouseEvent` imports are five lint occurrences; future annotations defer evaluation, so these are not ordinary import-time crashes. Fix for type checking/introspection. |
| Duplicate UI audio methods | Four MainWindow methods are redefined later in the same class. They silently override earlier implementations. Consolidate and check duplicate methods in CI. |

## Performance checks that passed

All eight existing benchmarks passed. The dedicated run reported:

- 50,000 memory records trimmed in 0.412 s.
- Traceback lookup across 50,000 files in 0.051 s.
- 150,000 CSV rows filtered with 0.19 MB peak traced Python allocation.
- 100,000 CSV rows exported with 0.07 MB peak traced Python allocation.
- 100,000 text lines processed with 0.387 MB peak traced Python allocation.
- Bounded reading of a 21.17 MB file used approximately 34 KB peak traced allocation.

The dedicated benchmark run overlapped the second test suite and used tracemalloc instrumentation. Treat its wall times as indicative checks, not clean throughput baselines. Traced Python allocation is not total process RSS or native-library memory.

## Recommended work order

1. Fix API-key fallback names, consolidate local TTS, and schedule warm-up correctly. Add branch-specific regression tests.
2. Connect worker crashes to the GUI safely, replace quadratic email trimming, and rotate crash logs.
3. Make tests hermetic: isolate capability caches, mock capture/network/hardware seams, repair obsolete fixtures, and use real offscreen Qt widgets where native types matter.
4. Add development dependencies and CI: full pytest, Python-version-aware runtime lint, duplicate-method checks, and separate Windows/Linux jobs. Keep network/hardware tests opt-in.
5. Establish a clean performance baseline: import time, window-ready time, first-token/first-audio latency, p50/p95/p99 Qt heartbeat gaps, RSS, thread counts, and queue sizes over a 30–60 minute session.
6. Then optimize measured costs: lazy provider imports, bounded queues/history, one TTS worker, batched logs, and measured GC scheduling. Retest audio responsiveness while tools, screen monitoring, and animations run together.
7. Finish or remove the inactive local coordinator, duplicate popup/audio methods, and incomplete placeholder paths before exposing them as supported features.

No live microphone/speaker conversation, real mail-client send, GPU inference session, native Linux run, or long-duration soak test was performed. These checks cannot certify the absence of all failures or performance regressions.
